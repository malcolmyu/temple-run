# Temple Run — extracted audio + UI textures

Generated by `/tmp/export_temple_audio_ui.py` (re-runnable) from
`~/Downloads/temple-run.xapk` → `com.imangi.templerun.apk` → `assets/bin/Data/*`.
Source APK and `/tmp/temple-unity-data/` untouched. 28/28 clips and 7/7 textures exported; 0 failures.

## How
- **AudioClip payloads are not in the `.assets` file.** Each clip is a ~256 B
  `AudioClip` object in its own `assets/bin/Data/<hash>` file; the samples live in
  the sibling `assets/bin/Data/<hash>.resource`, itself an `FSB5` FMOD bank whose payload is
  raw PCM. Both files were copied to a temp dir and loaded together —
  `UnityPy.load(asset, resource)` — so `m_Resource.m_Source` resolves; then
  `clip.samples` returns a ready RIFF/WAVE blob. All 28 are `m_CompressionFormat=0`
  (PCM, 16-bit, 22050 Hz, mono or stereo), so nothing needed a Vorbis/ADPCM transcode.
- **Textures are self-contained**: `Texture2D.m_StreamData.path` is empty, pixel data is
  inline, so the `<hash>` file alone decodes (`tex.image`, ETC2/RGBA32 → RGBA PNG,
  Pillow, no rotation applied — checked visually, all upright).
- Duplicate `warning_icon` (two hashes, both 64×64) is pixel-identical; one kept.
- Checks: every WAV is 16-bit PCM/22050 Hz, all files >2 KB, `afinfo` clean; payload
  bytes diffed byte-identical against the FSB5 data section (no re-encode).

## Things the Web port must know
1. `slide.wav` and `footstepsTurn.wav` are **authored very quiet** (peak ≈ −38 dBFS,
   RMS ≈ −50 dB) — real content, not a decode bug (autocorrelation/spectrum check
   passed). Boost ~8–16× (or normalise to −3 dBFS) only for these two.
2. No run-footstep loop exists among the 28 clips. `footstepsTurn.wav` (0.19 s scuff)
   is the only footstep asset — re-trigger it every ~0.35 s at +18 dB for run cadence.
   `slide.wav` is the one clip with a seamless loop seam (start/end RMS delta 0.003) —
   correct for a looping slide/rush ambience.
3. `egUI_Buttons2x.png` is one 2048×2048 atlas (3.6 MB: logo, PLAY, coin/gem icons,
   banner ribbons, portraits, social marks) — slice by sub-rect, do not show whole.
4. `warning_icon.png` is 64×64 natively; death illustrations are 512×256 RGBA with alpha.
