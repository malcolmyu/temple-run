## 2. 20 分钟里实际看到的

### 2.1 路径

- 绝大多数时间是**单车道石桥/木桥**，宽约一个角色；
- **有多处 90° 转弯/绕角**（例如 104–116 s 的连续帧），但都是单车道转弯，不需要三车道换道；
- 有宽阔石台/多段桥面，且在 600–900 s 附近能看到**左右两条都可走的道路/岔路**；角色走中间或选一侧，当前网页版没有这种分支；
- 路径由石桥 → 木桥 → 断桥/石台 → 树根隧道 → 水/岩石区连续切换；
- 整体是“窄桥 + 连续弯折/起伏”，不是我们的“宽三车道 + 90° 弯”。

### 2.2 障碍

- 低树根/倒木：需要跳；
- 头顶树根/石拱/横梁：需要滑铲；
- 断桥/坑洞：需要跳；
- **整幅火墙**（约 10–12 min、14 min 多次出现）：横跨整条路，不是我们现在的“两侧火盆、中间安全”；
- 石墙/石台：单侧或整段封路；
- 障碍间距很大，且常和树根/石拱/藤蔓组合成“隧道感”；
- 没有看到我们现在的三车道石墩组合。

### 2.3 角色与镜头

- 角色**永久蓝/橙翼**，经常处于滑翔/悬空姿态；
- 镜头比我们更低、更近，角色占屏更大；
- 没有换道/转弯输入提示，基本是单线自动跑；
- 金币成串、钻石/道具较稀疏。

### 2.4 环境

- 暗绿丛林、深色水面、巨大树根、藤蔓、树冠隧道；
- 石拱门出现频繁，木桥有绳索/木板；
- 中后段出现水/岩石/断崖；
- 没有我们这种亮色天空/宽石墙的“神庙走廊”感。

### 2.5 UI

- 极简：分数、金币、暂停；没有我们的转弯箭头、障碍 cue、触控提示；
- 角色翅膀/分数倍率是 mod 效果，不带原版 UI。

## 3. 当前游戏 vs 视频

| 维度 | 视频 | 当前网页版 | 差距 |
| --- | --- | --- | --- |
| 路径拓扑 | 单车道 + 90° 转弯/绕角 + 左右岔路 | 三车道 + 72–108 m 转弯，无分支 | 路宽/分支/换道都不同 |
| 路宽 | 窄桥/窄石台 | 7 m 宽石路 | 视觉/玩法差异 |
| 障碍 | 低根、横梁、断桥、整幅火墙、石墙 | 8 类数据驱动，火塔中间安全 | 火墙/窄墙/树根尺度 |
| 动作 | 跳/滑为主 | 跳/滑/换道 | 换道在单车道视频里没有 |
| 角色 | 永久翼/滑翔 | 只有护盾翼 | mod 差异，不应直接抄 |
| 环境 | 暗绿丛林/水/岩/藤蔓/树冠 | 暗绿丛林但植被稀疏、石墙低模 | 美术密度 |
| 镜头 | 更近更低 | 已调近，但仍偏宽 | 需要按帧校准 |
| HUD | 极简 | 计分/转弯/提示/触控 | 信息更多 |
| 难度 | 20 min 不死是玩家水平；63×只影响计分 | 原版参数 + 2 lane 半边路 | 不能从视频推断难度 |
| 生成 | 单线连续主题 | 周期主题 + 单折线 | 需图结构/主题节点 |

## 4. 所有工作重点

### P0（必须先做，决定后面所有实现）

1. **参考优先级与模式架构**
   - 先定：三车道原版 / 视频单车道 / 双模式。
   - 推荐：**经典原版三车道**为默认，另开“视频模式”做单车道+永久翼；两者共用障碍/资源，不混参数。
   - 不先定这个，后面美术、镜头、障碍动作都会返工。

2. **难度校准**
   - 当前 72 m/障碍、双障碍 0、动作窗口 1 s，确实比之前简单。
   - 方案：`classic`（原版）与 `challenge`（36–48 m、双障碍 15%、窗口 0.55 s、速度 22）两个预设；默认档位需你定。
   - 验收：同一 bot 在 classic 2 km / challenge 2 km 的死亡率和障碍密度有明确区分。

3. **障碍 M4**
   - 23 个 OBJ 全量视觉：left/right/vert/narrow-wall/beam；
   - 新增视频里的**整幅火墙**作为独立定义（不再只有中间安全火塔）；
   - 树根/横梁/石墙尺度按 20 min 帧校准；
   - narrow-wall/beam 作为真实窄路边缘，不再只是程序化断口；
   - 验收：每个定义有截图 + 命中/动作测试。

4. **TrackPath 图结构（T / side path）**
   - 原版是四向图，T 路口/侧路径是核心生成能力；网页版仍是单折线。
   - 需要：节点图、分支、汇合、侧路径金币/障碍、主题节点切换。
   - 这是“严格原版”的唯一大改，建议单独里程碑，不和美术混。

### P1（视觉与体验）

5. **美术整体向视频靠**
   - 更密的树冠/藤蔓/巨大树根、石拱、绳索木桥、水/岩石区；
   - 石桥/石台材质、雾、灯火、萤火；
   - 控制面数/绘制调用，保持 60 fps / 移动端。
6. **角色与翅膀**
   - 默认只做护盾/复活翼；视频模式才允许永久翼；
   - 镜头再压低/拉近，角色占屏比例按帧校准。
7. **HUD 精简**
   - High Score 已改左上小胶囊；继续减少转弯箭头/提示对赛道的遮挡；
   - 保留必要的动作 cue，不照抄视频无提示。
8. **主题/关卡切换**
   - 原版 temple/plank/cliff 节点切换、cap 过渡；当前是周期函数。

### P2（工程与验收）

9. **性能/移动端**
   - 树冠/藤蔓 LOD、实例化、雾/阴影预算；目标首屏 draw calls +10% 内。
10. **测试**
    - spawner 10k seed、碰撞、bot 5k、视觉回归、CI。
11. **文档/部署**
    - 规则/路障/差距文档同步；Pages 验证。

## 5. 推荐实施顺序

1. 你定模式/难度（P0-1/P0-2）
2. 障碍 M4（P0-3）
3. TrackPath 图结构 + T（P0-4）
4. 美术/镜头（P1-5/P1-6）
5. HUD/主题切换（P1-7/P1-8）
6. 性能/测试/部署（P2）

理由：先定玩法骨架，再改障碍和美术；否则三车道/单车道切换会让所有碰撞和生成返工。

## 6. 需要你拍板

1. **模式**：经典三车道 / 视频单车道 / 双模式？（建议双模式，默认经典）
2. **难度默认**：classic 还是 challenge？
3. **火墙**：视频里的整幅火墙是否加入？原版 APK 火塔是中间安全，二者冲突。
4. **永久翼**：只放在视频模式，还是默认也给？
5. **TrackPath 图结构**：本轮是否直接做 T/侧路径？
6. **美术预算**：为了视频密度，移动端是否接受 DPR 1.25/阴影关闭？
7. **“全部实现”的验收边界**：以原版机制 + 视频美术为准，还是视频 mod 也复刻？

## 7. 不做的假对齐

- 不把 63×、1 亿分、永久翼写进经典模式；
- 不把“视频单车道”直接覆盖三车道原版；
- 无图结构前，不声称 T 路口/侧路径已经严格还原。


## 8. APK 素材结论补充

APK 没有可复用的模块化路面/T 岔路/木板 mesh；`templeT*`、`plankT*`、`templeToPlankCap*` 只是 prefab 名，几何是运行时生成。可用的只有墙/门/岩石/树和 `wallTexture.webp` atlas。左右道路、右侧残缺路面、石头/木板整段路面都必须程序化实现，详见 [50-video-differences.md](50-video-differences.md)。
