# 原版路径生成规则取证：普通进度阶段

更新：2026-10-31。范围是当前APK原版代码普通阶段的静态证据，不代表当前网页生成器已完整移植。

## 可复现取证

运行 `python3 tools/inspect-native-path-pacing.py BASE.apk libil2cpp.so`。脚本只读IL2CPP metadata、ELF relocation和指令，不执行原版库。结果保存于 `target/temple-run/analysis/native-path-pacing.json`，含二进制哈希、字段名、指令校验及解码后的float32常量。

依据：`GameController.HandlePacing`126eb5c..126eed0，`PathElement.GetRandomPathElementForSide`12e3f4c..12e4504。完整反汇编已保存在既有native-methods/native-generation目录。

## 普通连续跑动的阶段表

单位：距离列是GameController.DistanceTraveled本局进度；间距列是原版Spaces计数。原版基本资源格12网页世界米，但计数门槛本身不是精确路段长度分布。

|进度范围|转角最小格数|障碍最小格数|金币串最小格数|近距追加障碍概率|
|---|---:|---:|---:|---:|
|0–250|12|6|12|0|
|250–500|10|5|10|0|
|500–1000|8|4|9|0.05|
|1000–1500|6|4（继承）|8|0.05（继承）|
|1500–2000|5|3|7|0.10|

边界由float比较跳转决定。1500/3250/4500常量从6975f8/697580/697584直接读取，不能按观感猜成1500/3000/4000。0.05、0.1、0.15、0.175从MOVZ/MOVK组合出的64位字段写入值解码，JSON保留实际float32精度。

表按正常单调增加的进度串联，部分字段继承之前阶段的写入。不能将各行当作任意传送后都立即成立的独立配置。4500以上从126f150跳入新的普通阶段写入126f184..126f1a0：最小转角2、障碍2、金币串6，概率0.2；此前停止在126eed0附近造成“后期未知”的遗漏已纠正。快速转弯段、远端覆盖和其他路径级别分支尚未完整审计，普通阶段表不是完整生成器。

## 资格门槛

- metadata验证PathElement.SpacesSinceLastTurn=0x78、SpacesSinceLastObstacle=0x7c、BackToBackObstacleCount=0x80。
- 允许转角的全局开关启用且`SpacesSinceLastTurn >= sMinSpaceBetweenTurns`，才通过转角间距门槛（12e3f74..12e3f7c）。通过不等于必定转弯。
- 障碍先要求`SpacesSinceLastTurn != 1`和`BackToBackObstacleCount < sMaxBackToBackObstacles`；构造默认后者为2（12e3fac..12e3fc4）。后续还有类型/道路几何过滤。
- 如果`SpacesSinceLastObstacle >= sMinSpaceBetweenObstacles`则通过这个间距门槛；不足时取整数Range(0,1000)，只有roll严格小于`doublePercent*1000`才保留障碍资格（12e3fdc..12e4034）。不是“距离满足后仍按概率删掉所有障碍”。
- 候选列表先按类型、关卡、道路方向、空间与开关等条件过滤，12e44e8调用`Range(0,eligibleCount)`取列表索引。这里没有恢复出一张可直接替换网页所有weight字段的全局权重表，重复条目/特殊分支仍可能影响最终概率。

## 当前网页实现的对应边界

- 游戏当前已按实际进度增量扩展：前方缓冲360米，分组长度取max(120,当前原版转角最小格数×12)+0/24/48。120安全下限、随机抖动、覆盖袋、每4组切主题、T路口25%、分路长度36仍明确是网页可玩性假设。
- 之前仅取构造默认“转角间距6格”不够：正常开局HandlePacing会将其改为12格。不能把构造默认与实际运行期阶段混为一谈。
- 已接入本表的转角最小间距约束及500进度开放滑铲横梁/火塔、1500开放窄路的限制；障碍近距追加概率和金币串间距尚未按完整候选过滤移植。4500以上也已采用已验证的普通阶段约束；快速转弯的独立修改仍未接入。
- 游戏从489米的固定入门段开始，仅随实际RunStats进度追加未来路段，保留已有路段。CoursePlan默认6000的离线构造接口仅供既有工具/测试使用；运行时显式指定489。
- 现有石桥/木桥、路口/分路、长坑/窄路的可玩性证据继续有效。本报告不以规则取证替代实际游玩，也不改变已通过的地图参数。


## 4500后分支补证

`126ee94`读取4500，比较后分支至126f150；126f184/188/194组合出`0x3e4ccccd00000002`，低32位为障碍2，高32位float32为0.20000000298。126f18c加载6、126f190加载2，再于126f198/19c/1a0分别写金币串间距、转角间距和障碍/概率。新工具检查对应指令并解码组合值；不是从“像是更难”推测参数。

随后126eee8开始读取独立`sIsFastTurnSection`，126ef40以Range(0,4)和<=2决定是否翻转，126efc4按另一个常量调整转角间距并钳制至少2，126f01c将金币串间距改0。这些是后续需要单独移植的分支，不能把普通阶段表说成全部最终参数。

## 快速转弯独立状态补证（第19轮）

`tools/inspect-native-fast-turn.py`只读验证原版指令、metadata字段和既有场景导出，输出`analysis/native-fast-turn.json`。

- 控制器0x134/138/13c分别为DistanceToTurnSection、DistanceToTurnSectionEnd、DistanceTraveledSinceLastTurnSection。序列化默认1000、100、0；1000–1500普通阶段将入段门槛改850，4500+改750。中间阶段继承与其他重置仍需整体审计，不能假定始终1000。
- ComputeDistanceTraveled126e438..43c按本局度量增量累加独立计数。HandlePacing126eefc/ef2c要求严格超过当前状态门槛；等于时不抽签。
- 一旦超过，先清零，再Range(0,4)；0/1/2翻转状态，3保持原状态。因此未入段也必须重新累计，已入段可能延长；不能每帧75%抽签，也不能固定跑100米后必定退出。
- 快速状态覆盖当帧普通转角最小格数：乘float32 .6499999761581421、向零取整、钳制至少2；金币串间距0，其他普通参数保持。不是把普通地图所有长度固定乘.65。
- `nativeFastTurn.ts`纯状态模型与边界单测已落实，但**未接入运行中CoursePlan**。现有120米成组几何下限、端帽/短转角/候选过滤需要一起改造和实际浏览器验证；目前不得将快速转弯列为已完成玩法。

## 快速转弯运行接入（第20轮）

上述第19轮“未接入”状态已被本轮替代。Game按真实RunStats度量增量更新独立快速状态，使用隔离种子随机流；重开清零。入段门槛按已验证写入/继承采用1000、1000进度后850、4500进度后750，段内门槛100。CoursePlan追加分组读取当前状态，保留已生成前缀。

快速组使用max(48,缩减后转角最小格数×12)+0/12/24，当前不混入障碍/主题转换，复用既有转角/T路口组装。48安全下限、抖动和障碍排除是网页假设，不是原版候选概率或长度分布；普通成组段保留120安全下限。360前方缓冲意味着已生成段不会随状态翻转重新抽签，短段在玩家前方稍后出现。金币串0已存在状态模型中，但完整金币串候选生成尚未接入。

浏览器2种子各9000物理米，均自然经过短段（分别生成14/5组），失败结算和重开通过。2种子各7500的石木桥、窄路、分路双向与合流、无无敌长坑回归17项通过。短段普通左右键分别安全换道，放任错过转角按missed失败，重开快速状态归零。不能将这批验证说成真机实时操作或完整原版生成器证明。

## 障碍资格门槛接入（第22轮）

`nativeObstacleGate.ts`接入已取证的GetRandomPathElementForSide门槛：转角计数恰为1排除、连续数>=默认上限2排除；障碍间距达到当前阶段最小值直接允许，不足时才抽Range(0,1000)，严格小于float32(percent*1000)才允许。必须对乘法结果也做float32舍入，否则JS double会把.2阶段随机值200错误纳入。资格不等于最终候选选择。

CoursePlan适配：用独立种子流以25%提出一次候选，对treeJump/treeTrip/treeSlide/flameTower/plankBeam在同组原障碍后36米复制；离下一路口至少36米，排除快速段和长坑/窄墙等成组几何。25%候选率、同类复制、36米动作/路口留白是网页可玩性假设。不是原版完整候选权重。36米即3格，部分早期阶段需要近距概率门槛；后期普通最小值<=3时直接允许符合原版门槛语义，但没有声称所有后期近距类型都已恢复。

100种子2000阶段完整地图单测生成177组安全双障碍；六种子各9000物理米自然跑动全部到达，五条出现双横梁/火塔/滑铲树根并通过，第六条没有抽到双障碍（该覆盖断言为false，其他运行/闭环检查通过）。另用两树根间隔36米的隔离场景验证两次实际跳跃后仍playing；它不是自然生成双树根证据。

## 三主题的距离切换（第29轮）

静态来源：`GameController.HandlePacing126eb24..126eb58`、`ChangeLevel1272c80..1272d70`；可重跑 `python3 tools/inspect-native-theme-pacing.py /tmp/com.imangi.templerun.apk /tmp/temple-libil2cpp.so`，输出`analysis/native-theme-pacing.json`及ChangeLevel汇编。场景初值见`game-controller-scene-source.json`。

- PathLevel1木桥、2神庙、3悬崖。累计的是ComputeDistanceTraveled实际度量增量（字段130），不是道路物理米或帧数。
- elapsed严格大于门槛才进入抽签，先清零，Range(0,4)的0/1/2切换，3保持原主题；抽签失败仍重新累计。神庙用字段128门槛，其他用12c。
- 默认门槛神庙500/其他200；进度1000起450/250（字面量6972e0），4500起375/300（697078）。普通单向进度下中间档继承此前值。
- 木桥必转神庙且不再次抽签；神庙Range(0,2)的0→木桥、1→悬崖；悬崖0→神庙、1→木桥。
- 网页适配：独立种子随机流、初始489米覆盖段、360米前瞻与完整安全过渡组。请求只追加未来路，不修改既有障碍；过渡组至少120米且不混障碍。切换请求度量距离与实际surface边界分别记录，不能把门槛当实际可见主题长度。原版生成缓冲、全部候选与权重未恢复。离线无progress覆盖清单仍保留旧4组交替，仅用于资产/障碍覆盖测试，运行时不用它。
- 悬崖已有独立level、terrain、脚步音分派，当前复用石桥地面/现有峡谷边缘，未声称恢复悬崖专用网格或专属候选分布。木桥↔悬崖仍用现有木石过渡组件；专用资源待补。
- 原版HandlePacing先抽签再写本帧难度门槛；网页按当前进度选档，不校准跨档同帧顺序。
