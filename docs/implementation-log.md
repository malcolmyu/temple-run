# 整体设计实施记录

当前设计：[game-design.md](game-design.md)。记录按设计阶段推进，目标目录百分比不作为实施优先级。

## P1-1：方向输入仲裁（2026-11-01）

已实现：将普通左右、路口窗口、T口出口、手动覆盖加速自动选择、暂停/开场/坠落拦截提取到独立纯模块 `target/temple-run/web/src/game/inputRouter.ts`。返回值只有ignore、lane、turn；输入决策不依赖音效、渲染或存档，也不能直接制造绊倒/死亡。game.ts负责读取世界快照与执行已确定的结果，跳/滑动作及后续持续转向仍保留原实现。

修复：原move先queueTurn、后判断nativeFalling，坠落中的角色可能继续提交路口转弯。现在在同一仲裁入口先拦截。其余窗口仍为现有6米前/2米后，没有冒称本轮重测出原版手感参数；本项目普通左右换道语义来自用户明确要求。

验证：

- `npm run temple:test:input-router`：双方向、窗口边界、远处/错误方向回退换道、最外道限幅、T双向、手动替换自动选择、手动重复、非运行/开场/坠落拦截。
- `npm run temple:test:turn`、类型检查、生产构建通过。既有bar图片路径及音频chunk提示保留。
- `tools/test-temple-input-router.browser.js`：15项实际输入/碰撞回归通过，显式reference路线用于稳定验证。含键盘/指针、空中/滑铲横移、T两臂、树根真实碰撞、漏转死亡、结算与重开。
- 正常生成seed1自然4000米，28次转弯，随后真实失败、结果和重开通过；没有seek/spawn/保护诊断。
- 受控坠落用例：seek148、指定路口153、放置坑，角色phase playing/falling true、路口剩余4.45米时，转弯请求返回false、右输入不改车道、不排队。此为诊断复现，不冒充自然遇到。
- 正常跑到T口前后诊断激活boost，自动左转排队后，实体Right切为右出口，autoQueued清除且车道不变，证明单次输入不同时换道。普通无保护实体Right/Left仍lane1/0且playing。
- 20项浏览器检查全通过，原始状态见 `target/temple-run/analysis/gameplay-input-router.json`，正常输入画面同名PNG。结束精确恢复测试开始的用户原始存档。

尚未完成：P1中的GameSession状态机/runId结算契约提取、统一事件边界；P2中的正常起点随机生成与统一可达性检查；其余节奏、内容与真机验收仍按设计推进。本轮是方向仲裁边界落地，不宣称输入设备层或整个P1已经完成。

## P1-2：本局会话状态与结算边界（2026-11-01）

已实现：新增独立GameSession，拥有menu/playing/paused/dying/ended的合法转换、本局runId、死亡数、翅膀/宝石复活次数和结算锁。game.ts不再分别保存paused/reviveUsed/runCommitted/runWingRevives；统一通过会话转换后向UI发布phase。resetWorld只重建世界，不创造会话身份；start才创建新ID，复活保留同一ID。开场仍采用原introHeld规则，本轮未新增UI的starting/reviving阶段，避免混入表现改动。

结算契约：仅ended且有正距离的未提交局可以提交；在调用同步账本前锁定本局，拒绝重复或重入提交。回调抛错可重试，但这只保证会话锁恢复，不承诺对部分修改的账本做事务回滚。保留现有“最后离开结果才入账”“未结束局主动重开/退出则放弃”策略。runId与最近提交收据目前在内存中，**跨刷新未结束局恢复、持久化账本收据与跨标签页并发仍未实现**，不把本轮称为持久化事务系统。

实际验证：

- 真实HUD启用翅膀，致命失败自动复活；同一runId，wingRevives1。
- 真实暂停按钮后advance5000，位置不变；真实继续按钮恢复。
- 再次失败进入结果时银行仍100、局数仍原1，本局可用宝石复活，未提前入账。
- 点击真实“宝石复活◆2”：10→8，runId不变、gemRevives1；重复请求不再扣款，第三次死亡后再次请求也被拒绝。
- 最终本局13金币，点击真实“再跑一次”后银行100→113、局数1→2；新runId不同、最近收据指向旧runId，死亡/复活标记清零。重复返回菜单银行仍113，未重复提交。
- 15项方向输入/触摸/树根/漏转/结算回归通过；正常生成seed1自然4000米、失败与重开通过，前后runId符合预期。无seek/spawn/无敌诊断，时间通过advance加速，不能替代真人实时手感。

共25项浏览器检查全通过。原始状态/账本在 `target/temple-run/analysis/gameplay-game-session.json`，PNG为最终结果真实界面。GameSession单测另覆盖非法状态、一次宝石复活、重复死亡、重入提交、回调失败重试、空局不结算与新局重置；既有utility目标单测、类型检查和生产构建通过。旧bar图片与音频chunk提示保留。结束精确恢复本轮开始的用户原始JSON，刷新后会话为menu/runId null。

规则来源：本项目整体架构设计与现有已验证的网页复活/结算策略；不是本轮新逆向的原版状态机。本轮没有发现并声称修复新的重复结算复现，而是移除分散状态、建立独立契约并验证现有防重行为。

剩余：统一领域事件边界、持久化提交策略（如需断线恢复另行设计），P2从起点生成正常路线与可达性校验。下一轮优先推进P2最影响可玩性的固定开局/程序生成边界，不继续围绕目标目录逐条扩展。
