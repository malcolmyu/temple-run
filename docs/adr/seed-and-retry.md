# 种子、重试与操作回放的契约

状态：采用。2026-11-01。

正常游戏按实际进度调节生成，不是预先由种子展开的一张固定地图。用户目标是玩法完整，不要求跑动流程与录像相同。

## 已验证的行为

`CoursePlan`使用种子随机流，同时读取生成时的距离进度、主题请求与快速转角状态。实际跑动速度又受跳跃、滑铲、绊倒、加速及时间步长影响，因此同一种子下不同操作可以改变未来课程。长坑还会按实际速度进行可跨越性判断。开局三个基础片段使用独立种子流，后续仍按进度产生。

[对照证据](../../target/temple-run/analysis/gameplay-seed-contract.json)验证：相同种子、相同进度调用序列产生相同片段/转角/障碍；相同种子但不同进度序列，开局一致，后续实际拓扑不同。不能把它包装为“重复同一种子就完整重试同一路线”。

## 当前产品决定

保留当前“再跑一次”的新局语义，不新增没有完整保证的“重试本次路线”。历史reference模式只是明确的录像对照，不是为正常模式提供回放的替代方案。

种子是运行环境的一部分，不是完整录像、关卡ID或操作轨迹。运行时课程和路径已做历史回收，也不能以当前窗口数组冒充完整旧路线。

## 后续正确回放所需边界

完整操作记录至少应含版本、种子、开局升级快照、难度/角色、每步时间、输入的消费阶段与顺序、连续横移值，以及暂停、起跑、翅膀与复活等直接UI命令。只录按键时间无法保证等价：当前正常frame在tick前消费输入，诊断advance在tick内消费输入；改变阶段会改变跳跃时间窗和排队的前向力。

播放必须隔离库存、扣款、目标和结算副作用，并核对版本/资产与关键状态校验。以新进度重新生成同一种子，不算已完成回放；以强制瞬移或保护让它通过，也不算复现成功。

该记录系统仍未实现。本决定限定承诺，不把一个未完成的工程功能从验收表中划掉，也不改变现有生成规则来凑“同一路线”。
