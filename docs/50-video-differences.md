# 参考视频 vs 当前版本：50+ 差异清单

## 采样

- 视频：<https://www.bilibili.com/video/BV1GW411N794/>（1:02:24）
- 0–300 s：每 1 s，300 帧；
- 0–600 s：每 2 s，300 帧；
- 600–1200 s：每 5 s，120 帧；
- 104–116 s：每 2 s，转角序列；
- APK：`analysis/track/track-report.md`、`obstacle-manifest.json`、`wallTexture.webp`。
- 公开分帧页：<https://malcolmyu.github.io/temple-run/screenshots/ref20/>

视频是 63×/永久翼 mod：**20 min 不死主要是玩家水平**，不是难度证明；倍率只影响计分。

## APK 逆向结论（关键）

1. APK **没有模块化路面、T 路口、岔路 mesh**。`track-report.md` 的结论：
   “no road tile, no junction, no modular track kit”；只有墙、门、岩石、树。
2. `plankStraight*` / `plankT*` / `templeT*` / `templeToPlankCap*` 是 **prefab 名字/运行时拼装逻辑**，没有可直接导出的路面几何。
3. 可用素材只有：
   - `track-wall-straight-a/b`、`track-wall-corner-a`、`track-gate-a`、`decor-rock-a`、`decor-tree-a`；
   - `wallTexture.webp` 里同时有**石砌路面、木板、苔藓、浮雕**等 atlas 区域；
   - `narrow-wall/beam` 是障碍矮墙，不是道路边缘/残缺路面。
4. 所以：**左右道路、右侧残缺、石头/木板整段路面**都必须程序化生成；不能靠“再找一个 OBJ”解决。

## 最关键的五组

1. **左右道路/T/汇合**（#1–3、#21–24、#51）——APK 没有现成 mesh，必须程序化图。
2. **整段路面材质切换**（#9–12、#21–23）——石头/木板长段 + cap；当前是周期 tile。
3. **右侧残缺路面**（#18）——不是黑色 void，而是碎裂石沿/木断口 + 水下崖面。
4. **整幅火墙 + 低树根**（#26–27、#33–34）——和当前火塔/大树 prefab 行为不一致。
5. **美术密度/树冠/藤蔓/石拱**（#36–44）——当前暗绿基调有了，但植被密度和层次差很多。

## 与 50 条对应的实现含义

- 需要新增 `TrackGraph`/side-path，而不是继续往 `TrackPath` 加转弯；
- 需要新增 `SurfaceSegment`（stone/wood，长段、cap、broken edge），而不是每 12 m 换 terrain；
- 需要新增 `FireWall` 障碍定义、低根/横梁/断桥/岩石的视觉与 hitbox；
- APK 能提供的只有墙/门/石/树和 atlas；路面和岔路必须自己做，不能假称“从 APK 找到了”。
